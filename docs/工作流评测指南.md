# 工作流评测指南

`code-helper evaluate` 用于在隔离临时项目中重复执行真实 CLI 工作流，同时检查验收条件和采集本地可观测的效率指标。默认场景不调用付费 Agent；需要真实 Agent acceptance 时，必须显式提供 runner 适配器。评测不访问业务仓库，也不会根据输出大小伪造 Token 消耗。

## 快速开始

运行内置最小场景，默认使用三个同条件样本：

```bash
npm run evaluate
```

也可以直接运行并把 JSON envelope 保存为后续基线：

```bash
code-helper evaluate --samples 3 --json > evaluation-baseline.json
```

报告包含每个样本的总耗时、子进程往返次数、stdout/stderr 字节数、文件数量与磁盘增长，以及最小值、最大值、均值和 p50。临时项目默认在每个样本完成后删除。

## 自定义声明式场景

场景只能描述夹具文件、code-helper 参数数组和验收断言，不执行任意 Shell：

```json
{
  "schemaVersion": 1,
  "id": "project-initialization",
  "name": "项目初始化",
  "description": "验证初始化与结构化任务查询。",
  "fixtureFiles": [
    {
      "path": "package.json",
      "content": "{\"name\":\"fixture-project\"}\n"
    }
  ],
  "steps": [
    {
      "id": "init",
      "description": "初始化 Codex 项目资产",
      "args": ["init", "codex"],
      "assertions": [
        { "type": "exitCode", "equals": 0 },
        { "type": "fileExists", "path": "AGENTS.md" }
      ]
    },
    {
      "id": "tasks",
      "description": "读取任务列表",
      "args": ["tasks", "--json"],
      "assertions": [
        { "type": "exitCode", "equals": 0 },
        { "type": "jsonPathEquals", "path": "action", "equals": "tasks.list" }
      ]
    }
  ],
  "thresholds": {
    "maxFailureCount": 0,
    "maxAverageDurationMs": 5000,
    "maxDurationRegressionPercent": 20
  }
}
```

运行方式：

```bash
code-helper evaluate --scenario ./scenario.json --samples 3 --json
```

支持的断言类型为 `exitCode`、`stdoutIncludes`、`stderrIncludes`、`jsonPathEquals`、`fileExists` 和 `fileContains`。夹具、文件断言和命令输入路径必须是临时项目内的相对路径；命令使用本地非交互 allowlist，递归 `evaluate` 和联网的 `version check` 会被拒绝。

## 真实 Agent runner

场景可增加 `agent.prompt`，并在命令行显式传入可执行 runner：

```bash
code-helper evaluate --scenario ./agent-scenario.json --samples 3 --agent-runner ./agent-adapter --json
```

runner 在隔离临时项目中执行，从 stdin 接收 prompt，向 stdout 只返回一个 JSON：

```json
{ "passed": true, "tokens": 1234, "turns": 6 }
```

runner 负责适配 Codex、Claude Code 或其它 Agent 的真实调用与认证；code-helper 不替用户选择服务、不自动联网，也不保存 runner 的输出正文。`tokens` 和 `turns` 必须来自 Agent 的真实观测，缺失时继续标记为 `unknown`。

## Token 外部观测

本地 CLI 子进程无法看到 Agent 服务端 Token。没有外部数据时，每个样本和聚合报告都会明确写为 `unknown`。如果调用方能从真实观测系统获得数据，可按样本顺序传入非负整数；缺失值继续写 `unknown`：

```bash
code-helper evaluate --samples 3 --token-observations 1200,unknown,1180 --json
```

这些值的来源会标记为 `external`，工具不会根据 stdout 字节数或耗时推算 Token。

## 基线与阈值

`--baseline` 接受之前生成的裸报告，或 `evaluate --json` 生成的 Agent envelope。基线必须与当前场景 ID 相同：

```bash
code-helper evaluate --scenario ./scenario.json --samples 3 --baseline ./evaluation-baseline.json --json
```

报告总会展示耗时和磁盘增长相对基线的百分比；只有场景显式配置 `maxDurationRegressionPercent` 或 `maxDiskGrowthRegressionPercent` 时，回归才成为失败门禁。验收或阈值失败返回退出码 2，输入错误返回 1，全部通过返回 0。
